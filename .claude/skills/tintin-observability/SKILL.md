# tintin-observability

Determine current logging/monitoring infrastructure, do not invent alerts or create paid services. Diagnose via timestamps, release SHA, affected routes and reproducible evidence. Add bounded structured diagnostics with privacy, redaction and sampling. Do not leak personal information, tokens or order details to public logs. Match monitoring to user-impacting failures, avoid intrusive reload prompts, and verify rollback/incident response guidance. Distinguish temporary provider outages from regression.

## Completion evidence
Report files touched, targeted verification results, repository commit/PR when applicable, and explicit limits. This Skill never overrides AGENTS.md, DESIGN.md, or production safety rules.
